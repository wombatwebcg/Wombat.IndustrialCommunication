# IEC104 主站接入指南

适用对象：需要在 Gateway 或其他业务工程里读取现场 104 主机的开发者。本文覆盖连接、总召、遥控、值缓存、事件与探测工具，对应三阶段计划的阶段二。

## 1. 依赖

```
Wombat.IndustrialCommunication
  ├─ Wombat.Network 1.1.9
  ├─ Wombat.Extensions.DataTypeExtensions 1.1.1
  └─ Microsoft.Extensions.Logging.Abstractions
```

2026-11 起 104 主站随 `Wombat.IndustrialCommunication` 包一起发布，命名空间仍是 `Wombat.IndustrialCommunication.Iec104`，引用一个包即可。

104 的运行路径不接入核心的 ChannelManager 与 TCP 适配器。业务工程若要和现有 Channel 体系对接，在业务侧订阅事件并自行写入缓存，不要把主站塞进 ChannelManager。

## 2. 最小用法

```csharp
using Wombat.IndustrialCommunication.Iec104;
using Wombat.IndustrialCommunication.Iec104.Model;
using Wombat.IndustrialCommunication.Iec104.Options;

var options = new Iec104MasterOptions
{
    Host = "192.168.1.10",
    Port = 2404,
    CommonAddress = 1,
    InterrogationTimeout = TimeSpan.FromSeconds(30),
};

var master = new Iec104Master(options);
master.ValueReceived += (_, e) => Console.WriteLine($"IOA={e.Value.Ioa} 值={e.Value.Numeric}");
master.LinkStateChanged += (_, e) => Console.WriteLine($"链路 {e.State} {e.Message}");

await master.ConnectAsync();
var result = await master.InterrogateAsync();

if (!result.Completed)
{
    Console.WriteLine($"总召未完成，已收 {result.ReceivedCount} 点，缺失 {result.MissingIoa.Count} 点");
}

await master.DisposeAsync();
```

`ConnectAsync` 内部完成 TCP 建链与 STARTDT 握手，握手失败会抛 `TimeoutException`，不会返回半连接状态。

## 3. 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| Host / Port | 127.0.0.1 / 2404 | 从站地址 |
| CommonAddress | 1 | 只处理该公共地址的帧；从站返回 0 时按通配处理 |
| K | 12 | 未确认 I 帧上限，发送被阻塞在此 |
| W | 8 | 累计收到多少 I 帧后回 S 帧 |
| T1 | 15s | 发送确认超时，也是 TESTFR 超时 |
| T2 | 10s | 收到数据后回 S 帧的最长等待，必须小于 T1 |
| T3 | 20s | 空闲后发 TESTFR 的间隔 |
| ConnectTimeout | 30s | TCP 建链超时 |
| InterrogationTimeout | 30s | 一次总召的整体超时 |
| CommandTimeout | 15s | 遥控每一步的超时 |
| AutoReconnect | false | 断链后自动重连 |
| ReconnectDelay | 5s | 重连间隔 |
| CyclicInterrogation | 0 | 周期总召间隔，0 表示关闭 |
| InterrogateOnConnect | false | 连接激活后立即总召 |
| EnableTrace | false | 是否输出收发帧 |

现场调试建议打开 `EnableTrace`，稳定运行后关闭，避免日志量过大。

## 4. 事件与值缓存

| 事件 | 触发时机 | 用途 |
|---|---|---|
| ValueReceived | 收到任一数据对象 | 实时推送，事件在读取线程触发，处理要快 |
| LinkStateChanged | 连接、激活、断开、故障 | 状态展示与重连提示 |
| FrameTraced | 收发每一帧（仅 EnableTrace） | 抓包级别的排查 |

值缓存以 IOA 为键：

```csharp
if (master.TryGetValue(16385, out var value))
{
    // value.Numeric / value.Boolean / value.Quality / value.Timestamp
}
```

`Iec104Value` 同时给出数值与布尔语义：单点为 0/1，双点用 `Numeric` 保存原始状态码（1 分、2 合），`Boolean` 只对「合」为 true。带时标类型会填 `HasTimestamp` 与 `Timestamp`，无时标时 `Timestamp` 等于接收时间。

工程量的系数与偏移不在主站做，主站保存协议原值；需要工程量时用点表的 `ToEngineering` 换算。

## 5. 总召

```csharp
var result = await master.InterrogateAsync();
```

| 字段 | 含义 |
|---|---|
| Completed | 是否收到激活终止 |
| Confirmed | 是否收到激活确认 |
| TimedOut | 是否因整体超时结束 |
| ReceivedCount | 实际收到的数据对象数 |
| ExpectedCount | 点表预期的数据点数；未配置点表时等于 ReceivedCount |
| MissingIoa | 点表中有、总召未收到的 IOA |
| Duration | 耗时 |

总召超时不抛异常，返回 `TimedOut=true` 的结果，方便探测工具输出部分数据。只有链路故障才抛异常。

## 6. 遥控

```csharp
await master.SingleCommandAsync(24577, true);
await master.SingleCommandAsync(24577, true, Iec104CommandMode.SelectAndExecute);
await master.DoubleCommandAsync(24578, Iec104DoublePointState.On);
```

| 返回字段 | 含义 |
|---|---|
| Accepted | 是否被接受并完成 |
| Negative | 是否收到否定确认 |
| Cause | 最后一次响应的传送原因 |
| Stage | Select / Execute / Termination |
| TimedOut | 是否超时 |

被拒绝属于正常业务分支，不抛异常。只有链路故障才抛异常。选择-执行模式下，选择被拒绝会直接返回，不再发送执行帧。

## 7. 断线与重连

`AutoReconnect` 打开后，主站每秒检查一次连接，断开后按 `ReconnectDelay` 重连；重连成功且 `InterrogateOnConnect` 为真时自动重新总召。重连过程通过 `LinkStateChanged` 通知。

关闭 `AutoReconnect` 时，断链只抛事件，重连策略完全由调用方决定。Gateway 如果需要与现有 Channel 的重连策略统一，应选择关闭并自行控制。

## 8. 探测工具

```bash
dotnet run --project tools/Iec104Probe -- \
  --host 192.168.1.10 --port 2404 --ca 1 \
  --telemetry 遥测.csv --discrete 遥信.csv --command 遥控.csv \
  --out report.json --trace
```

输出四段：总召结果、类型分布、样本值、点表对照。JSON 报告用于跨次比对：

```json
{
  "interrogation": { "completed": true, "receivedCount": 1116, "expectedCount": 1116 },
  "types": [ { "typeId": 13, "count": 818, "ioaMin": 16385, "ioaMax": 17202 } ],
  "pointTable": { "total": 1120, "matched": 1116, "missing": [] }
}
```

每次现场点表变更或主机升级，跑一次并 diff 报告，就能区分是点表变了还是主机行为变了。

## 9. 现场实测步骤

1. 先用 `--trace` 只连不总召，确认 STARTDT 能否完成；若失败，记录是否收到 STARTDT con。
2. 总召并保存 JSON，看类型分布：遥信是 1 型还是 30 型，遥测是 13 型还是 9/11 型。
3. 看点表对照：缺失点集中在哪一段，判断是 IOA 基准差一位，还是按类型分段。
4. 用 `--telemetry-base`、`--discrete-base`、`--command-base` 反复试，直到命中率 100%。
5. 把最终基准写入点表说明的基线记录。

## 10. 常见问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| STARTDT 确认超时 | 从站未实现 STARTDT，或要求先发初始化帧 | 抓包确认；必要时调整从站兼容开关 |
| 总召收到 0 点但完成 | 公共地址不匹配 | 核对 CA，或先用 0 通配试探 |
| 总召点数对但值错位 | IOA 基准差一位或按类型分段 | 用报告中的 IOA 区间反推偏移 |
| 序号不连续导致断链 | 从站重发或本机丢包 | 检查网络与从站 k 窗口配置 |
| 时标比本地时间差 8 小时 | 从站按时区解释 CP56Time2a | 主站按本地时间解析，需业务侧确认时区口径 |
| 运行一段时间后断链 | t3 测试帧未被响应 | 确认从站是否回 TESTFR con |
