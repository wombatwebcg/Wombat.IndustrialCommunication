# IEC104 从站模拟器联调手册

模拟器用 CSV 点表或内置演示点表启动一台 104 从站，用于主站开发、第三方主站联调、异常场景构造。阶段三交付。

## 1. 启动

```bash
dotnet run --project tools/Iec104SlaveSimulator -- \
  --telemetry 遥测.csv --discrete 遥信.csv --command 遥控.csv \
  --port 2404 --ca 1 \
  --telemetry-base 16385 --discrete-base 1 --command-base 24577 \
  --cyclic 10 --simulate
```

不指定任何 CSV 时使用内置演示点表：10 个遥测、4 个 SOE 遥信、1 个遥控，便于快速冒烟。

从站启动后持续运行。交互终端里可用命令改值；stdin 被重定向时进入非交互模式，收到 Ctrl+C 或进程终止才退出。

## 2. 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| --telemetry / --discrete / --command | 空 | 三张点表，可只给其中一张 |
| --port | 2404 | 监听端口，0 表示由系统分配 |
| --bind | 0.0.0.0 | 绑定地址 |
| --ca | 1 | 公共地址 |
| --ioa-base | 1 | 全局地址基准 |
| --telemetry-base / --discrete-base / --command-base | 空 | 分类地址基准，优先于全局 |
| --cyclic | 0 | 周期上送间隔（秒），0 关闭 |
| --soe | true | 遥信是否使用带时标类型 30 |
| --select-before-operate | 关 | 强制先选择后执行 |
| --no-init-frame | 关 | 不发送初始化结束帧 |
| --double-command | 关 | 遥控点按双点命令 46 处理 |
| --simulate | 关 | 每 2 秒生成正弦遥测与随机遥信变位 |
| --trace | 关 | 打印收发帧十六进制与语义 |

三张 CSV 的转发号都从 0 开始，共用一个基准会在 IOA 上重叠。联调时必须按类别分段，例如遥测 16385 起、遥信 1 起、遥控 24577 起。

## 3. 交互命令

| 命令 | 作用 |
|---|---|
| set <IOA> <值> | 写遥测，超过死区才上送 |
| toggle <IOA> | 翻转遥信状态，SOE 点带时标 |
| invalid <IOA> <0/1> | 设置或清除无效品质位 |
| status | 显示监听状态、客户端数、点数 |
| quit | 退出 |

示例：

```
set 16385 220.5
toggle 1
invalid 16386 1
status
```

## 4. 典型场景

### 4.1 验证主站总召

启动模拟器后跑探测工具，核对点数：

```bash
dotnet run --project tools/Iec104Probe -- --host 127.0.0.1 --port 2404 \
  --telemetry 遥测.csv --discrete 遥信.csv \
  --telemetry-base 16385 --discrete-base 1
```

期望输出 `1116/1116 点`，类型分布为 13 型 818 点、30 型 298 点，点表对照缺失 0。

### 4.2 验证突发与 SOE

用 `toggle` 改一个 SOE 点，主站应在 `ValueReceived` 中收到 30 型帧，`HasTimestamp` 为真，时标取变位时刻。用 `set` 改遥测，只有变化超过死区才上送。

### 4.3 验证遥控

默认直接执行；加 `--select-before-operate` 后，直接执行会被否定确认，必须先选择。遥控请求通过 `CommandRequested` 事件暴露，模拟器默认接受并打印。

### 4.4 验证总召期间的抑制

模拟器在总召进行时暂停突发与周期上送，值变化会排队，总召结束后再发。用 `--trace` 可以看到这个行为：总召确认之后只有 20 原因的帧，直到激活终止。

### 4.5 验证 k 窗口与确认

818 个遥测按每帧 30 个分 28 帧，未确认帧达到 k=12 时从站会停发，等主站 S 帧确认后继续。主站不确认时，总召会停在半途，用于测试异常处理。

## 5. 与第三方主站联调

1. 确认模拟器监听地址与端口，防火墙放行。
2. 第三方主站填同一公共地址；若对方要求 IOA 从 1 开始，就把 `--telemetry-base` 设为 1 并只加载遥测表。
3. 先做总召，确认对方能收到 13 型与 30 型；如果对方只认 1 型，加 `--soe false`。
4. 遥控先试直接执行；对方若强制选择-执行，加 `--select-before-operate`。

## 6. 已知限制

- 数据点仅支持 1、3、13、30、31、36 型；9 型与 11 型在点表中会被跳过。
- 总召不分级，一次性上送全部数据点（按类型分帧）。
- 选择态保存在内存，进程重启即丢失。
- 不实现电度总召（101）与文件传输。
- 同一 CA 下所有连接共享同一份数据，序号状态按连接隔离。

## 7. 故障排查

| 现象 | 检查 |
|---|---|
| 启动报端口占用 | 换端口，或用 `netstat -ano | findstr 2404` 查占用进程 |
| 主站连上但总召 0 点 | 公共地址是否一致；点表是否加载成功 |
| 点数对但值全 0 | 未加 `--simulate`，且没有手工 `set` |
| 遥信没有时标 | 点表类型不是 30，或启动时加了 `--soe false` |
| 遥控一直否定确认 | 开了选择-执行但未先选择；或 IOA 不在遥控点表中 |
| 日志里看不到帧 | 未加 `--trace` |
