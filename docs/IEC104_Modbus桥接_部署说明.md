# IEC104 → Modbus TCP 桥接：部署说明与寄存器表

版本：v1.2（阶段一 + 阶段二 + 阶段三）　　适用工程：`Wombat.IndustrialCommunication.Extensions.IEC104.ModbusBridge`　　对应计划：`IEC104_Modbus桥接计划.md`

## 1. 已完成范围

**阶段一（只读镜像）**：104 主站缓存中的遥测、遥信按点表镜像到 Modbus 寄存器，下游用任意标准 Modbus TCP 主站轮询。

**阶段二（命令通道）**：4x 命令区写入触发 104 遥控，两段确认、状态与原因回写、30 秒确认窗口、白名单、Direct / SelectAndExecute 两种方式、审计日志。

命令通道**默认关闭**。关闭时写命令寄存器只会把状态置 8、原因置 4，不产生任何 104 动作。

**阶段三（工程化）**：JSON 配置文件与启动校验、映射表 CSV 导出与版本哈希、断链读策略（陈旧值 / 异常码）、3 客户端容量测试、运维手册。

## 2. 拓扑与端口

```
现场 104 主机 (2404)
        ↑ 104 主站（本库 Iec104Master）
        │
   Iec104ModbusBridge
        │ Modbus TCP 从站（默认 502，unitId 1）
        ↓
下游 SCADA / PLC（轮询 1x、3x、4x）
```

桥接层不改变 104 侧行为：STARTDT、总召、突发、k/w 窗口仍由主站负责。Modbus 侧是标准从站，被动应答，不主动推送。

## 3. 工程与依赖

```
Wombat.IndustrialCommunication.Extensions.IEC104.ModbusBridge
  ├─ ProjectReference → Wombat.IndustrialCommunication.Extensions.IEC104
  ├─ ProjectReference → Wombat.IndustrialCommunication（只用 ModbusTcpServer / DataStore）
  └─ TargetFrameworks: netstandard2.0;net8.0
```

104 扩展仍是零核心依赖；桥接工程是唯一同时认识两边的工程。阶段二给 `Iec104Master` 增加了一个 `SelectSingleCommandAsync`（只发选择帧），供两段确认的上半段使用。

## 4. 接入示例

```csharp
var table = Iec104PointTable.Load(new Iec104PointTableOptions
{
    TelemetryPath = "遥测.csv",
    DiscretePath = "遥信.csv",
    CommandPath = "遥控.csv",
    CommonAddress = 1,
});

var master = new Iec104Master(new Iec104MasterOptions
{
    Host = "192.168.1.10",
    Port = 2404,
    CommonAddress = 1,
    PointTable = table,
    AutoReconnect = true,
    InterrogateOnConnect = true,
    CyclicInterrogation = TimeSpan.FromMinutes(15),
});

await master.ConnectAsync();

await using var bridge = new Iec104ModbusBridge(
    new Iec104MasterValueSource(master),
    new ModbusBridgeOptions
    {
        BindAddress = "0.0.0.0",
        Port = 502,
        UnitId = 1,
        DiscreteBase = 0,
        TelemetryBase = 0,
        CommandBase = 0,
        HealthBase = 1000,
        WordOrder = ModbusFloatWordOrder.Abcd,

        // 阶段二
        EnableCommands = false,                                // 默认关闭，现场确认流程后再开
        CommandMode = Iec104CommandMode.SelectAndExecute,
        AllowedCommandIoa = new[] { 24577, 24578 },            // 可选白名单
        ConfirmTimeout = TimeSpan.FromSeconds(30),
    },
    logger);

await bridge.StartAsync();
```

点表里的 `ForwardNo` 决定地址，`Ioa` 只用于访问 104。追加点位时把转发号往后排，已有地址不会移动。

## 5. 寄存器表

地址公式：`地址 = 基准 + 转发号 × 步长`。基准可配置，下表按默认值（遥信/遥测/命令基准 0，健康基准 1000）列出。

| 区 | 功能码 | 步长 | 本例范围 | 读写 | 内容 |
|---|---|---|---|---|---|
| 1x 离散输入 | 02 | 1 | 0..297 | 只读 | 298 个遥信 |
| 3x 输入寄存器 | 04 | 2 | 0..1635 | 只读 | 818 个 float，每点两个寄存器 |
| 4x 保持寄存器（命令） | 03/06/16 | 3 | 0..11 | 读写 | 4 个遥控，命令/状态/原因 |
| 4x 保持寄存器（健康） | 03 | 1 | 1000..1007 | 只读 | 链路与刷新状态 |

> 计划文档 9.2 节把遥测写成“保持寄存器”，以第 4 节的区域规划为准：遥测在 3x，必须用功能码 04 读。已与使用方确认。

### 5.1 命令点布局

每个遥控点占三个连续寄存器：

```
CommandBase + n*3 + 0   命令寄存器（写）   0=无动作 1=请求合 2=请求分 3=确认合 4=确认分
CommandBase + n*3 + 1   状态寄存器（读）   0..9
CommandBase + n*3 + 2   原因寄存器（读）   否定原因码
```

命令寄存器写入后**立即回 0**，所以“读回 0”只表示写入已被消费，不代表执行成功；结果看状态寄存器。

状态码：

| 状态 | 含义 |
|---|---|
| 0 | 空闲 |
| 1 | 选择中（已发选择帧，等待设备确认） |
| 2 | 待确认合 |
| 3 | 待确认分 |
| 4 | 执行中 |
| 5 | 成功 |
| 6 | 被拒绝 |
| 7 | 确认超时 |
| 8 | 未启用 |
| 9 | 点忙（保留） |

原因码：

| 码 | 含义 |
|---|---|
| 0 | 无 |
| 1 | 从站否定确认 |
| 2 | 超时（选择或确认） |
| 3 | 104 链路不可用 |
| 4 | 命令通道未启用 |
| 5 | IOA 不在允许列表 |
| 6 | 确认值与选择不符 |
| 7 | 点忙（保留） |

### 5.2 健康区

| 偏移 | 绝对地址 | 内容 | 判读 |
|---|---|---|---|
| 0 | 1000 | 104 链路状态 | 0 断开、1 已连接未激活、2 激活 |
| 1 | 1001 | 遥测最后刷新距今秒数 | 持续增长说明遥测不再更新 |
| 2 | 1002 | 遥信最后刷新距今秒数 | 同上 |
| 3 | 1003 | 已映射遥测点数 | 本例 818 |
| 4 | 1004 | 已映射遥信点数 | 本例 298 |
| 5 | 1005 | 点表版本（映射表 CRC16） | 变化说明点表被改过 |
| 6 | 1006 | 桥接运行状态 | 0 停止、1 运行 |
| 7 | 1007 | 保留 | 恒 0 |

断链后遥测、遥信寄存器**保持最后值不变**，这是刻意设计：把 0 或 NaN 写成真实值更危险。下游必须用健康区判断数据是否可信。

## 6. 编码规则

### 6.1 遥测

IEEE754 单精度拆成两个 16 位寄存器，字序可配：

| 字序 | 低地址寄存器 | 高地址寄存器 | 适用 |
|---|---|---|---|
| `Abcd`（默认） | 高 16 位 | 低 16 位 | 多数国产 SCADA |
| `Cdab` | 低 16 位 | 高 16 位 | 部分 PLC 与海外组态 |

例：42.5 → 0x422A0000 → Abcd 下是 `16938, 0`。

### 6.2 遥信

单点直接写 1x。双点按“合=1、其余=0”降维，**中间态与不确定态在 Modbus 侧不可见**。

### 6.3 不可表达的信息

- 时标：Modbus 无时间语义，104 的 CP56Time2a 在桥接层丢弃；
- 品质位：104 的品质描述符不透传，链路异常只能通过健康区发现；
- 双点中间态：如上。

## 7. 刷新时序

```
104 事件 → 记录 IOA 到脏集合（去重）
        → 刷写循环每 50ms 取一批（单次上限 2000 点）
        → 解析地址 → 整批写 DataStore（一次持锁）
```

- 104 侧变化到 Modbus 寄存器可见：最迟约 50ms；
- 加下游轮询周期，才是端到端延迟；
- 链路重新激活时会全部重点一遍，避免漏掉断链期间的变化；
- 健康区每个周期整体重写，只有一个写入者。

## 8. 命令通道

### 8.1 两段确认流程

```
下游写 1（请求合）
   → 命令寄存器回 0，状态 1（选择中）
   → 104 选择帧被接受，状态 2（待确认合）
下游写 3（确认合）
   → 状态 4（执行中）→ 104 执行帧 → 状态 5（成功）
```

写入语义：

| 当前状态 | 写入 | 结果 |
|---|---|---|
| 0/5/6/7 | 1 或 2 | 发起选择，进入 1；Direct 方式直接进入 2/3 |
| 0/5/6/7 | 3 或 4 | 忽略（没有待确认的选择） |
| 1 | 任意 | 忽略，状态保持 |
| 2 | 3 | 执行合，进入 4 |
| 2 | 4 | 忽略，原因 6 |
| 2 | 1 | 忽略（重复请求同一方向） |
| 2 | 2 | 覆盖：重新选择分，进入 1，不执行 |
| 3 | 4 | 执行分，进入 4 |
| 3 | 3 | 忽略，原因 6 |
| 3 | 2 | 忽略（重复请求） |
| 3 | 1 | 覆盖：重新选择合，进入 1，不执行 |
| 4 | 任意 | 忽略，状态保持 |

**周期写不会误确认。** PLC 每个扫描周期重复写 1 只会反复“请求合”，不会触发执行；只有写 3 才执行。这是本方案相对“同值写两次”的核心优势，组态时必须讲清楚。

**确认不是身份确认。** Modbus 无法标识客户端，A 请求、B 确认在协议层无法禁止。二次确认防的是误碰和误组态，不防人为串通。

### 8.2 Direct 与 SelectAndExecute

| 方式 | 写 1/2 | 写 3/4 |
|---|---|---|
| SelectAndExecute（默认） | 发 104 选择帧 | 发 104 执行帧 |
| Direct | 仅本地置状态，不发帧 | 发 104 直接执行帧 |

两种方式下 Modbus 侧交互完全一致，切换只影响桥接层内部是否真的发选择帧。

选型建议：

- 现场设备要求“先选择后执行”时必须用 SelectAndExecute；
- 若设备的选择有效期短于 ConfirmTimeout，操作员在窗口后段确认会被设备拒绝（状态 6、原因 1）。要么调小 ConfirmTimeout，要么改 Direct；
- 接现场主机后先实测选择有效期，再定默认方式。当前代码默认 SelectAndExecute。

### 8.3 超时

| 阶段 | 超时 | 结果 |
|---|---|---|
| 选择中（状态 1） | `SelectTimeout`（默认 15s，与 104 t1 对齐） | 状态 6，原因 2 |
| 待确认（状态 2/3） | `ConfirmTimeout`（默认 30s） | 状态 7，原因 2，本地选择清空 |
| 执行中（状态 4） | 104 主站 `CommandTimeout`（默认 15s） | 状态 6，原因 2 |

### 8.4 安全约束

- `EnableCommands` 默认 false；关闭时写命令寄存器只置状态 8、原因 4，不动作；
- 可选 `AllowedCommandIoa` 白名单，未列出的点状态 6、原因 5；
- 命令方式与现场设备能力对齐，见 8.2；
- 每次命令写一条审计日志（ILogger）：结果、IOA、命令值、状态、原因；
- 已知限制：DataStoreWrittenTo 不带客户端标识，无法记录来源 IP；需要溯源时只能靠连接事件与时间窗关联。

## 9. 配置文件、导出与断链策略

### 9.1 配置文件

`ModbusBridgeConfiguration` 把 104 连接、Modbus 端口与基准、命令通道、断链策略、点表路径收进一个 JSON。相对路径按配置文件所在目录解析。

```csharp
var configuration = ModbusBridgeConfiguration.Load("bridge.json");
configuration.EnsureValid();                 // 一次性报出全部问题
var table = configuration.LoadPointTable();
var options = configuration.CreateOptions();
var masterOptions = configuration.CreateMasterOptions(table);
```

校验内容：

| 类别 | 检查 |
|---|---|
| JSON 语法 | 解析失败带行号与列号 |
| Modbus | 端口 1..65535、从站号 1..247、基准非负、健康区不越界、刷写周期为正 |
| 命令 | 两个超时为正、白名单里的 IOA 为正 |
| 104 | 主机非空、端口与公共地址范围、k/w ≥ 1、重连间隔为正 |
| 点表 | 至少一张 CSV；配置了的路径必须存在 |
| 地址映射 | 转发号重复/为负、地址溢出、区域重叠、无法映射的点类型（构造桥接时统一报出） |

完整字段模板与运维用法见 `IEC104_Modbus桥接_运维手册.md`。

### 9.2 映射表导出

`ModbusRegisterMap.ExportCsv()` 返回 CSV 文本，`ExportCsv(path)` 写文件（UTF-8）。列为：区域、地址、寄存器数、转发号、IOA、类型、描述。`VersionText` 给出点表版本的十六进制文本，与健康区 5 的值一致。

发布前导出一份随版本归档，组态方与现场都用同一份表。

### 9.3 断链读策略

| `stale.readMode` | 行为 | 适用 |
|---|---|---|
| `LastValue`（默认） | 数据区保持最后值，靠健康区告警 | 大多数现场：下游能区分“值没变”和“链路断了” |
| `Exception` | 断链超过 `timeoutSeconds` 后，功能码 01/02/04（数据区）返回异常码 0x04，功能码 03（健康区与命令状态）始终可读 | 下游只会看数值、不看健康区时 |

`Exception` 模式的代价：部分组态软件遇到异常码会判定“从站故障”并触发重连风暴，甚至把通道标红。开启前先确认下游的异常处理策略。无论哪种模式，链路激活后立即恢复读。

## 10. 部署检查清单

- [ ] `UnitId` 与下游组态的从站号一致。不一致时请求被静默丢弃，不返回异常。
- [ ] 下行读遥测用功能码 04、读遥信用 02、读健康区与命令状态用 03。
- [ ] 遥测一次最多读 125 个寄存器，1636 个寄存器需要 14 次请求；下游按 125 分批。
- [ ] Linux 下 502 属于特权端口，需要 root 或 setcap / AmbientCapabilities，或改用 1502 等高端口。
- [ ] Modbus 无认证，端口只绑内网。
- [ ] 开放命令前确认：设备是否需要先选择、选择有效期多长、ConfirmTimeout 是否匹配。
- [ ] 命令点只把“命令寄存器”开放为写，状态/原因寄存器设为只读，避免被组态误写。
- [ ] 命令通道白名单按实际遥控点配置，不用空值放开全部。
- [ ] 点表版本（健康区 5）与现场发布记录比对，变化必须人工确认。
- [ ] 下游用健康区 0/1/2 做数据可信判断，不能只看数值是否正常。
- [ ] 断链策略按下游能力选：只能看数值的用 `Exception`，会因异常码重连的用 `LastValue`。
- [ ] 配置文件里的 CSV 路径按部署目录核对；启动后比对日志里的点表版本与发布记录。

## 11. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 读请求超时/无响应 | unitId 不匹配、端口未监听、防火墙 | 核对 UnitId，netstat -an 看 502 是否 LISTEN |
| 读返回异常码 02 | 地址越界。DataStore 长度 65535，可用 0..65534 | 检查基准与转发号乘积 |
| 遥测值与实际不符 | 字序配错 | 切换 WordOrder 试 Abcd / Cdab |
| 数据不刷新，健康区 0=0 | 104 断链 | 查 104 侧 2404 连接、STARTDT |
| 数据不刷新，健康区 0=2 但 1/2 持续增长 | 104 侧无变化且未开周期总召 | 打开 CyclicInterrogation |
| 写命令后状态一直是 8 | EnableCommands 没开 | 打开开关并重启桥接 |
| 写命令后状态 6、原因 5 | IOA 不在白名单 | 把 IOA 加入 AllowedCommandIoa |
| 确认时状态 6、原因 1 | 设备拒绝执行；常见于选择已过期 | 调小 ConfirmTimeout 或改 Direct |
| 状态 7 | 30 秒内没写确认码 | 正常超时，重新走请求流程 |
| 读数据区返回异常码 04 | 开启了 `stale.readMode = Exception` 且链路已陈旧 | 查健康区 0；不需要该行为就改回 LastValue |
| 启动即抛 ModbusBridgeConfigurationException | 转发号重复/为负、地址越界、命令区与健康区重叠 | 按异常里的列表逐条改点表或基准 |
| 部分点地址有空隙 | 转发号不连续 | 正常，按段拆分批量读；启动日志有告警 |

## 12. 已验证内容

单元测试与集成测试共 95 项（含既有 104 用例）全部通过。

阶段一覆盖：

- 地址分配：298 遥信 0..297、818 遥测 0..1635、4 遥控 0..11、健康区 1000..1007；
- 校验：转发号重复、为负、地址越界、命令区与健康区重叠、不支持的点类型；
- float 编码：正负零、极值、NaN、无穷、两种字序往返；
- 集成：1116 点镜像逐点一致；从站改值 1 秒内可见；启动初始镜像全 0；停从站后健康区链路状态归 0、刷新秒数持续增长。

阶段二覆盖（真实 TCP + SlaveHarness + ModbusTcpClient）：

- 写 1 → 状态 2 → 写 3 → 状态 5，104 侧依次收到选择帧、执行帧；
- 待确认合时写 2 → 状态回到 3，104 侧只收到选择帧，没有执行帧；
- 待确认合时写 4 → 状态保持 2，原因 6，104 侧无动作；
- 待确认后不写确认 → 状态 7，原因 2；
- 命令通道关闭时写入 → 状态 8，原因 4，104 侧无动作；
- 白名单外的 IOA → 状态 6，原因 5，104 侧无动作；
- Direct 方式 → 请求阶段不发帧，确认阶段只发执行帧。

阶段三覆盖：

- 配置文件：完整配置正确映射到选项与主站参数；非法端口/从站号/基准/超时/白名单/缺失 CSV 一次报全；JSON 语法错误带位置；重复转发号与地址溢出在构造桥接时被拒；
- 映射导出：CSV 行数等于点位数加表头、列顺序正确、含逗号与引号时正确转义、可写文件；
- 断链策略：LastValue 模式断链后仍返回最后值；Exception 模式断链超时后读请求失败；
- 容量：3 客户端 × 1 秒周期 × 1116 点并发轮询无失败（默认 5 秒，可用环境变量延长到 10 分钟）。
